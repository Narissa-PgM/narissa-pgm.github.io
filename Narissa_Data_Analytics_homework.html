🗺️ Part 2 · CRISP-DM Model — Sample Phrases reference

🧠 What a strong CRISP-DM model looks like
Each phase below shows best practices and a worked sample phrase you can reference when you write your own. Use these as a model for what a clear, actionable output looks like at each step.
📌 Scenario

A company wants to increase customer retention. Follow the six CRISP-DM phases below — each one shows best practice and a sample phrase you can model your own work on.

🎯
Phase 1
Business Understanding Why are we doing this?
Goal → KPI → Decision
📐 Best practice — how to write a goal, KPI & decision
  • Goal — start with a verb + outcome + scope. Make it specific and time-bound. Bad: “improve retention.” Good: “reduce monthly churn by 3 points in 2 quarters.”
  • KPI — pick one primary metric that is measurable, owned, and moves with the goal. Add a target. Retention rate = active users at end of month ÷ users at start
  • Decision — state the action the analysis must unlock. Who will do what differently? If no decision changes, the analysis has no business value.
✅ Sample phrases — retention scenario
Goal “Reduce monthly churn by 3 percentage points over the next two quarters.”
KPI “Retention rate — % of subscribers active at end of month. Target: ≥ 92%.”
Decision “Which customer segments to target with which retention offers.”
🔍
Phase 2
Data Understanding What data do we need?
Identify sources → Check quality → Explore signals
📐 Best practice — mapping data to the goal
  • For each KPI, ask: which datasets tell me about this? List the sources by name (e.g., subscription DB, usage logs, cancellation table).
  • Check coverage (does it include all customers?), granularity (per user? per day?), and freshness (how old?).
  • Flag any gaps or quality risks now — they become prep tasks in Phase 3.
✅ Sample phrases — retention scenario
Sources “Subscription data, usage activity logs, cancellations list.”
Coverage “All active + churned subscribers over the last 12 months.”
Risks “Usage logs may have gaps; cancellations list may be incomplete for involuntary churn.”
🧹
Phase 3
Data Preparation Clean & shape the data
Clean → De-duplicate → Define target
📐 Best practice — preparing data for modeling
  • Clean — fix date formats, unify time zones, handle missing values with a documented rule (not silently).
  • De-duplicate — one row per customer per period. Decide the rule for merging duplicates.
  • Define the target — make “churn” explicit: no activity for 30 days? cancellation event? Document the definition so it’s reproducible.
  • Feature engineering — create signals like tenure, days since last login, support tickets per month.
✅ Sample phrases — retention scenario
Cleaning “Standardize dates, remove duplicate subscription rows.”
Target “Churn event = cancellation OR 30 days of zero activity.”
Features “Tenure, monthly logins, avg session length, support tickets, plan tier.”
🧠
Phase 4
Modeling Find the patterns
Segment → Find drivers → Score risk
📐 Best practice — modeling choices
  • Start simple. A logistic regression or decision tree is often enough to identify churn drivers — and it’s explainable to stakeholders.
  • Segment first. Group customers by behavior (power users, casual, at-risk) before modeling — segments make results actionable.
  • Balance interpretability and accuracy. If you use a complex model, pair it with SHAP or feature importance so the business can act on it.
  • Always output a score. A churn probability per customer is what turns analysis into an action.
✅ Sample phrases — retention scenario
Technique “Logistic regression + decision tree for explainability.”
Segments “Power users, casual users, dormant-at-risk.”
Output “Churn-risk score (0–1) per customer.”
📏
Phase 5
Evaluation Does it hold up?
Validate → Check metrics → Stakeholder review
📐 Best practice — evaluating before deploying
  • Technical checks — accuracy, precision/recall, AUC. Choose metrics that match the business cost of errors.
  • Business checks — do the segments make sense? Would acting on them realistically move the KPI?
  • Stakeholder validation — walk through the results with the retention team. If they don’t trust it, it won’t be used.
  • Document limitations — what the model does not capture (e.g., external churn reasons).
✅ Sample phrases — retention scenario
Technical “AUC 0.82, precision 0.74 on holdout set.”
Business “Top 20% risk segment matches known at-risk accounts.”
Sign-off “Retention team confirms segments are actionable.”
🚀
Phase 6
Deployment Put it to work
Dashboard + Action plan + Monitor
📐 Best practice — deploying & monitoring
  • Deliver to the decision-maker. A monthly churn dashboard beats a one-off report — it keeps the KPI visible.
  • Pair insight with action. Every score or segment should link to a specific play (e.g., “at-risk → send win-back offer”).
  • Monitor drift. Track model accuracy monthly — customer behavior changes and models decay.
  • Close the loop. Measure whether the retention offers actually improved the KPI, and feed that back into the model.
✅ Sample phrases — retention scenario
Deliverable “Monthly churn-risk dashboard + segment-level retention action plan.”
Action “At-risk segment → automated win-back offer.”
Monitoring “Monthly model refresh + KPI tracking.”

📖 Key concepts reference

Structure

  • Structured: → Tables with rows/columns
  • Semi-structured: → JSON, logs
  • Unstructured: → Text, images

Data type

  • Qualitative: → Text labels/categories
  • Quantitative: → Numbers, KPIs

Temporal classification

  • Cross-sectional: → One-time snapshot
  • Time series: → Repeated over time
  • Panel: → Same entities tracked over time

🟨 Task 2 · Handle missing IDs with “Unknown” error handling

Without the 4th argument, XLOOKUP returns #N/A when an ID isn’t found. Adding "Unknown" as the if_not_found argument replaces the error with a clean label.
' ❌ Without fallback — shows an error' =XLOOKUP(B9, CustomerTbl[CustomerID], CustomerTbl[Segment]) ' → returns #N/A ' ✅ With fallback — shows "Unknown"' =XLOOKUP(B9, CustomerTbl[CustomerID], CustomerTbl[Segment], "Unknown") ' → returns "Unknown"
✅ Expected output — fallback comparison
  • Valid matches: return the correct segment (Enterprise, SMB, Startup).
  • Missing IDs (e.g., C-999): return “Unknown” instead of #N/A.

🟩 Task 3 · Repeat with INDEX + MATCH compatibility

INDEX + MATCH is the classic combo for older Excel versions or when you need maximum flexibility. Wrap it in IFERROR to get the “Unknown” fallback.
' INDEX returns the value at a given position; MATCH finds that position' =INDEX(CustomerTbl[Segment], MATCH(B2, CustomerTbl[CustomerID], 0)) ' Add IFERROR for the "Unknown" fallback' =IFERROR( INDEX(CustomerTbl[Segment], MATCH(B2, CustomerTbl[CustomerID], 0)), "Unknown" )
✅ Expected output — INDEX/MATCH mirrors XLOOKUP The Segment column returns identical results to the XLOOKUP version. Missing IDs still return “Unknown”.

Apply each task to the column shown. Use the formulas as a reference.

  • 2Remove hidden characters from Name using CLEAN (combinable with TRIM).
